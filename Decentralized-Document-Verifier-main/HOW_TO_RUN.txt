  PROBLEM: "Cannot connect to blockchain node at http://127.0.0.1:8545"
  FIX:     Terminal 1 (hardhat node) is not running. Start it first.

  PROBLEM: "Contract revert" or wrong contract errors
  FIX:     You forgot to update CONTRACT_ADDRESS in backend\.env after deploy.
           Repeat Step 2 and update the address.

  PROBLEM: Backend shows "CONTRACT_ADDRESS is not set"
  FIX:     Open backend\.env and make sure CONTRACT_ADDRESS has a value.
           Then restart the backend (Ctrl+C in Terminal 3, run command again).

  PROBLEM: "venv\Scripts\uvicorn.exe not found"
  FIX:     The virtual environment is missing. Run once:
             cd "...\backend"
             python -m venv venv
             venv\Scripts\python.exe -m pip install -r requirements.txt
           Then retry Step 3.

  PROBLEM: Frontend shows "Cannot reach the backend server"
  FIX:     Terminal 3 (backend) is not running. Start it and retry.

  PROBLEM: Port 8000 or 5173 already in use
  FIX:     Find and stop the old process:
             netstat -ano | findstr :8000
             taskkill /PID <pid> /F
           Then restart the service.

  NOTES
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  - Hardhat is a LOCAL test blockchain. All data is wiped on every restart.
    Documents registered in one session will NOT exist after a restart.

  - The PRIVATE_KEY in .env is a Hardhat test wallet. It is publicly known.
    Never use it on mainnet or any real blockchain.

  - The PINATA_JWT in .env is your real Pinata API key.
    Files uploaded to IPFS via Pinata persist even after restart.

  - PostgreSQL is optional. Without it the app uses the blockchain directly.
    If you install PostgreSQL later, create the database with:
      createdb docverifier
    The backend will automatically create the table on startup.
